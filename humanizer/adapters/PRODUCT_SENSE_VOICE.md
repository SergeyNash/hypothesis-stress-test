# PROJECT VOICE — Product Sense

Project / author: Hypothesis Stress Test — доклад Product Sense  
Default mode: business  
Audience: продакты, PM, лиды discovery; широкая продуктовая аудитория, не AppSec-ниша

Voice: уверенный сценический тон; ясно и по делу, без канцелярита и без «подкастной» разговорности

Preferred rhythm: короткие фразы для зацепок и вопросов в зал; абзацы — для объяснений; таблицы и списки — только где нужна структура слайда

Allowed texture: риторические вопросы, прямая речь в кавычках, устойчивые продуктовые термины

Forbidden patterns: цепочки `→` в устной речи; «в этом смысл», «смысл для зала»; серии «не X, а Y» подряд; объясняющие двоеточия в каждой строке; LinkedIn-пафос; Thinking Lab / JTBD-риторика

Domain terms (keep): backlog, CustDev, evidence, strategic fit, compliance, time-to-hire, HRD, CHRO, governance, RAG, Proceed with Validation, CISO, audit trail

Must preserve:
- фиксированное название доклада: «Стресс-тест продуктовых гипотез с помощью агентных ИИ-систем»
- 4 этапа конвейера на сцене (не 8 слоёв)
- 3 ошибки LLM (ровно три)
- порядок демо: HR Tech первый, AppSec — производственный кейс
- тайминг блоков в talk-outline
- рекомендация «продолжить с валидацией»

Must avoid:
- новые кейсы, цифры, обещания
- усиление слабых аргументов
- сглаживание противоречий в формулировках

Review checklist:
- [ ] 4 этапа конвейера на месте
- [ ] 3 ошибки LLM
- [ ] HR → AppSec
- [ ] «Продолжить с валидацией» не стало «строить MVP»
- [ ] HRD, CHRO, compliance, governance, backlog сохранены
- [ ] таблицы и минуты не сломаны
