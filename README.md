# Hypothesis Stress Test

Версия фреймворка <b>2.12.0</b>

HST — легковесный фреймворк для критического разбора продуктовых и сервисных гипотез языковой моделью. Это инструкции, роли и Markdown-шаблоны. Модель сама ищет и читает согласованные источники, сопоставляет основания, проверяет рассуждения и ведёт диалог с человеком.

Нет Python-оркестратора, машинного аудита, JSON-реестров, технических маркеров и обязательных CLI-команд внутри прогона. Результат каждого этапа — Markdown. Единственный просмотр — **HST · Прогресс** в терминале VS Code.

## Как устроен разбор

| Этап | Основной результат |
| --- | --- |
| Ролевой стресс-тест | Перспективы и возражения, hypothesis_summary.md, validation_questions.md |
| Локальные материалы | discovery_preview.md, evidence_inventory.md |
| Бизнес-контекст | business_context_analysis.md либо явные пробелы |
| Рынок | market_analysis.md |
| Синтез | hypothesis_map.md, hypothesis_digest.md |
| План проверки | customer_discovery_plan.md |
| Критический разбор | decision_review.md |
| Итог | human_report.md |

В текущем RUN_DIR также сохраняются input/hypothesis.md, принятые решения в run.md и короткий progress.md. Новой гипотезе — новая папка. Старые runs не используются как образцы без отдельного запроса. Источники, глубина, изменение формулировки и реальные развилки обсуждаются в чате. Полный запуск не требует одобрять каждый обычный шаг заново.

## Ограничение объёма работы

Основания и короткие точные цитаты сохраняются один раз; дальше этапы добавляют свои выводы и ссылки. Источник перечитывается при конкретном сомнении. Новый поиск нужен для открытого вопроса, способного изменить решение; ответ либо явно описанный пробел — точка остановки. Полный прогон не означает исчерпание БЗ.

Внутреннее улучшение не требует полного шаблона нового сервиса. План подробно описывает ближайшие решающие проверки, review проверяет ключевые тезисы и логику критериев; недоступное чтению остаётся непроверенным. Самодельные PowerShell/Python/shell/regex-проверки текста и временные выгрузки внутри прогона запрещены. Изменения инструкций не гарантируют соблюдение моделью: это проверяется контрольным повторением. [Порядок сравнения](implementations/dialogue-run.md).

## Установка

Открой корень своей базы знаний (например, DataB) в VS Code, установи Cline и настрой выбранную модель. Папка фреймворка находится внутри базы. В терминале DataB:

```powershell
python .\hypothesis-stress-test-main\scripts\setup_workspace.py --workspace . --terminal
```

После просмотра плана:

```powershell
python .\hypothesis-stress-test-main\scripts\setup_workspace.py --workspace . --terminal --apply --replace-framework-files
```

Скрипт подключает правила/skills и единственную задачу HST · Прогресс. Установка зависимостей просмотра выполняется только по явной команде, не в ходе анализа. Затем перезагрузи окно VS Code и начни новый чат Cline. Открыть просмотр: Terminal → Run Task → HST · Прогресс. Автоматический запуск при открытии папки зависит от разрешения VS Code на automatic tasks.

## Переход с 2.10 и прежних версий

Удаление старых файлов — намеренное изменение. Старый обновлятор ожидает удалённый extractor, поэтому для первого перехода используй актуальный обновлятор напрямую из официального репозитория. Выполняй между прогонами из DataB:

```powershell
$hstUpdater = Join-Path $env:TEMP "hst-update.py"
Invoke-WebRequest "https://raw.githubusercontent.com/SergeyNash/hypothesis-stress-test/main/scripts/update_workspace.py" -OutFile $hstUpdater
python $hstUpdater --workspace . --framework .\hypothesis-stress-test-main --terminal --apply
```

После слияния этой версии в main команда скачает её. Обновлятор сохраняет резервную копию, удаляет перечисленные прежние файлы фреймворка и синхронизирует новые правила. Старые пользовательские runs остаются нетронутыми. Известные прежние настройки/состояния интерфейсов при setup архивируются и убираются из активной установки; произвольные пользовательские файлы не удаляются.

В VS Code удали установленное ранее расширение **HST Pipeline Bridge** через Extensions → Uninstall, закрой его старый терминал и выполни Developer: Reload Window. Новый проект не содержит и не устанавливает этот модуль. Установка Python Progress Task не требует EXE, VSIX и поиска Actions-артефакта.

## Последующие обновления

Из DataB:

```powershell
python .\.hst\update.py --workspace . --apply
Get-Content .\hypothesis-stress-test-main\VERSION
```

Для настоящего Git-клона: сохрани свои локальные изменения, затем git pull --ff-only в папке репозитория и повтори setup для правил в DataB. После обновления — новый чат Cline. Исторические результаты не переводятся на новую схему автоматически.

## Чтение источников

Модель использует доступные клиенту инструменты чтения и поиска. Сам факт наличия локальной LLM не гарантирует чтение PDF/Word/Excel: это возможность клиента/его инструментов. Если формат недоступен, модель объясняет ограничение и предлагает экспорт/другой доступный способ. В HST нет обязательной установки парсеров и предварительной сериализации всей базы.

Для важных выводов сохраняются прямые ссылки и места в источнике, цитаты, периоды/единицы, контраргументы и ограничения. Ролевые симуляции не являются эмпирическими доказательствами. Завершение прогона не означает подтверждение спроса; технического RUN PASS больше нет.
