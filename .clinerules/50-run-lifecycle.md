# Verified phase lifecycle

For new runs `prepare` records `lifecycle_version: 1`. This rule takes precedence over older instructions to hand-write completion markers or emit standalone completed events. Historical runs are not automatically migrated; use their recorded protocol and explicit read-only diagnostics.

1. Confirm the input, call `run_control.py prepare --run-dir <RUN_DIR> --mode full`, and immediately show its actual HTML URL. This starts the viewer before any role/research stage. It also initializes empty source snapshot/claim ledger and the pending quality-review template. Empty files are NOT evidence or an approved audit. An HTTP launch failure is saved visibly; report the failure and separate-terminal serve command. Use viewer-unavailable only after telling the user the actual failure. Do not postpone the viewer until market/synthesis.
2. Obtain the source choice as described in `45-source-selection.md`. Preserve the confirmed choice on resume.
3. Before each stage: `python <FRAMEWORK_DIR>/scripts/run_control.py start --run-dir <RUN_DIR> --phase <phase>`. A previous marker alone is insufficient. Stop and repair the reported prerequisite if the command fails; never continue because files look complete.
4. Capture actual source fragments with source_snapshot BEFORE writing derived evidence. Preserve origins with `--channel local|confluence|internet`. Use `audit_records.py source --run-dir <RUN_DIR> --record <JSON_FILE>` to register source records and generate EVID blocks with separate canonical fields. The JSON has the source schema from implementations/run-quality.md; EVID records also include `inventory` with observation, relevance, relevance_reason, source_origin and evidence_status. Use only generated anchor IDs and exact source excerpts. Numbers require structured facts, including units, periods, populations and anchors. A source kind is customer_record/provider_record/primary_public/secondary_public/internal_analysis/simulation/search_log, never local_client/local_provider/synthetic. Simulations use kind/role=simulation. A missing-evidence gap belongs in a gap claim; it is not an empirical source.
5. Register derived claims with `audit_records.py claim --run-dir <RUN_DIR> --record <JSON_FILE>`. Claim kinds are fact/inference/gap/proposal; basis observed/derived/missing_evidence/simulation, never partial_evidence. Status conditional is separate from basis. Targets quote substantive conclusions in existing artifacts, not just contour status lines. Source registration checks the raw quote binding, but the agent must also read the referenced EVID/fragment and verify that the observation supports the claim. An audit about domain-controller copies cannot establish PostgreSQL restore failures. Do not merge customer/entity/database/time scopes merely because they share a document.
6. While processing, keep logging actual source operations and meaningful milestones. Do not fill missing calls retrospectively or substitute local/Confluence IDs for internet query tracks. Review inventory completeness with the user; record Retrieval Review accepted/waived with the actual reason. If all research is disabled, retain explicit gaps and synthetic roles, not fabricated evidence.
7. Before leaving each stage run:

```text
python <FRAMEWORK_DIR>/scripts/run_control.py complete --run-dir <RUN_DIR> --phase <phase>
```

This validates the stage, writes its canonical marker and records completed only after successful checks. It saves phase_validation.json and validation_history.jsonl. For business_context skipped due to genuine missing context add `--completion-status skipped_missing_context` and retain the gap artifact. `check-phase` runs the same output gate without creating a marker or declaring completion. Do not repair errors by lowering audit_version, changing a check to pass, making up source anchors or deleting counterevidence. If interrupted between marker and event, rerun complete: it rechecks artifacts, preserves history, and does not duplicate an existing completion. For intentional reruns first invalidate the phase and affected downstream phases/markers under the existing safe-write policy.

Local Evidence gate verifies the inventory, completeness review, registered EVIDs and captured sources without requiring future analyses. Business Context/Market/Synthesis additionally check the existing claims, research/context and source-bound audit without requiring the future human report or decision. Customer Discovery adds experiment checks. Decision Review requires complete quality review, experiment/decision alignment and service contracts. Human Report runs the full current-RUN_DIR validator. A failure blocks the next phase; reporting an actual blocker is appropriate when original sources are unavailable.

8. For Human Report use `run_control.py finish --run-dir <RUN_DIR>` (or complete --phase human_report). The helper creates the final marker only after full validation, preserves each attempt and records PASS/FAIL/ERROR for the actual target. Do not manually create validation_history or manufacture a successful run_validation. An interrupted attempt may leave status running; a checker exception is ERROR, not a completed run. Filesystem write failures must be reported; no helper can guarantee a record on unwritable storage.

The terminal/HTTP viewer rebuild the display from durable journal events if progress.json is stale. Warnings show marker/journal disagreement; they never count markers as completed phases. File existence, HTTP 200, balanced HTML tags and ten green markers are not equivalent to a validated run. Final user communication distinguishes execution state, coverage limits and evidence-supported conclusions.

## Early preparation handoff

New prepare records `phase_handoff_version: 1`. In full mode, the first confirmed source selection opens Facilitator preparation after the viewer is ready (or its host limitation was explicitly disclosed). Successful complete records preparation of the next untouched phase immediately, before returning control to the model. This is workflow preparation, not a claim that sources have already been read. Do not add invented source events. Existing errors, user waits and invalidations are preserved; changing source settings later does not reset a waiting phase. Phase mode never starts the next phase automatically. A start call on an already-running phase is idempotent.

Read the returned phase/result and do the current phase's work only after its running/preparation event exists. complete/finish reject a phase with no start recorded after its last invalidation. Never write the whole phase and only then call start. Legacy runs without the handoff flag are not retrofitted and their timestamps are not rewritten. A preparation/handoff failure is reported separately from the already-completed predecessor.

Incremental audits inspect current/prior artifacts and the claims bound to them, not future artifacts. A later synthesis issue must be diagnosed in synthesis, not as a business-context failure. The final audit still checks the entire run. Company-affiliation checks apply to explicit provider identity fields; customer/provider role notation, contour names and common technology/SLA abbreviations with slashes do not assert corporate affiliation. Do not remove meaningful ordinary phrasing just to appease a linter.


## One check per completed phase (2.8)

Normal path: prepare/sources-set → current phase work → one complete → use next_phase/next_prepared. A true next_prepared means the next running/preparation event already exists; do not add another start. Phase mode, an explicit resume, a waiting/error state, invalidation or legacy run still requires start. check-phase is for diagnosis only. Human Report uses one finish, with no separate preflight full validator unless recovering from a real failure.

Inside one successful controller command, checked content may be reused only by its scoped marker/event commit and immediate next-phase handoff. Receipts are in-memory, bound to RUN_DIR/phase and expire when the command finishes. Structural marker checks, source permissions and journal prerequisite states remain enforced. No persistent pass cache is used; the next independent command revalidates artifacts/sources. finish checks prior completion states and performs one complete whole-run audit. Broken inputs or missing sources still block completion.
