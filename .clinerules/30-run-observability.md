# HST · Прогресс

Единственный монитор — terminal_progress.py, запущенный пользователем через задачу VS Code HST · Прогресс. Он читает файлы и не участвует в анализе. Модели не нужно запускать Python, сервер или опрос состояния.

Сразу после создания разрешённого нового прогона запиши .hst/active-run.md:

```markdown
# Активный прогон
Прогон: runs/HYP-YYYY-MM-DD-NNN
```

В RUN_DIR/progress.md веди обычную краткую заметку:

```markdown
# Ход проверки
Начало: <доступное фактическое ISO-время с часовым поясом>
Статус: выполняется
Завершено этапов: 0/8
Текущий этап: 1. Роли

## Сейчас
Разбираю гипотезу и выбираю релевантные материалы.

## Выполнено
- Подтверждены формулировка и границы источников.

## Последние события
- <время> — <фактически выполненное действие или настоящий вопрос>
```

Для полного прогона начни с 0/8. Номер и название текущего этапа бери из таблицы в hst-run. При переходе обнови обе строки в той же записи заметки. Числитель — количество разных этапов, результаты которых успешно сохранены. При продолжении используй уже записанный счётчик. Повторное сохранение, ожидание ответа, ошибка и остановка сохраняют прежнюю долю. После пятого этапа при остановке оставь 5/8 и укажи статус «остановлен». Для последнего этапа оставь 7/8 до сохранения и human_report.md, и human_report.html. Затем запиши 8/8 и статус «завершён». Если достоверной доли нет, оставь счётчик незаполненным.

Обновляй при начале/завершении этапа, реальном ожидании или существенном результате. Новые события можно добавлять сверху. Не нужны записи каждую секунду, отдельный source-event на каждый файл и строгая схема. Не выдумывай timestamps. При завершении/отмене запиши Статус: завершён / остановлен и Окончание: <фактическое время>. Если время неизвестно — так и скажи, не считай его задним числом.

Если просмотр неполон или сломан, сообщи об этом один раз и продолжай содержательную работу. Не читай код монитора, не исправляй формат ради зелёных этапов и не подставляй фиктивные завершения. Диагностика интерфейса — отдельная задача по явному запросу.

## Достоверность отметок

При начале этапа записать, какой вопрос сейчас проверяется. Завершение отмечать только после успешного сохранения результата файловым инструментом; планируемый файл не считается созданным. При ошибке сохранения — статус «не сохранён», а не завершение. Не перечитывать все outputs ради обновления монитора.

Время брать только из доступных фактических часов клиента/среды с часовым поясом. Не запускать терминальные команды для времени, не получать timestamps из счётчика монитора и не придумывать будущие события. Если часы недоступны — «время не получено»; окончание и длительность считаются неизвестными. Не выдавать разность двух частичных отметок за длительность отдельной фазы. Отметки начала/завершения фаз хранить кратко здесь, не в новом журнале.
