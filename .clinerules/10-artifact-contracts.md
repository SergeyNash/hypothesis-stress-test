# Результаты — Markdown

Каждый прогон: runs/HYP-YYYY-MM-DD-NNN. Исходная карточка — input/hypothesis.md, контекст и принятые решения — run.md, ход работы — progress.md. Папка создаётся обычной записью файлов после ясного разрешения на запуск. Существующий прогон не перезаписывается без согласования.

| Этап | Основные результаты в outputs/ |
| --- | --- |
| Роли | role_outputs/<role>.md, hypothesis_summary.md, validation_questions.md |
| Локальные материалы | discovery_preview.md, evidence_inventory.md |
| Бизнес-контекст | business_context_analysis.md либо missing_business_context.md; external_research.md при внешнем исследовании/его ограничениях |
| Рынок | market_analysis.md |
| Синтез | hypothesis_map.md, hypothesis_digest.md |
| План проверки | customer_discovery_plan.md |
| Критический разбор | decision_review.md |
| Итог | human_report.md |

Это читабельные документы, не поля схемы. Названия нужны для навигации. Нет JSON-маркеров, обязательных keyword-токенов, allowlist outputs, скрытого ledger и технических FAIL/PASS. Содержательную проверку этапа модель делает по инструкции; существенные нерешённые вопросы показывает в диалоге. Не дублируй один вывод в нескольких технических реестрах.

В evidence_inventory сохраняй только релевантные основания: путь/URL и страницу/лист/ячейку, короткую точную цитату или наблюдение, значение для гипотезы и ограничения. ID EVID можно использовать для удобства, но отдельная регистрация и JSON не нужны. Источник и вывод должны быть различимы. Ролевые симуляции не являются эмпирикой.

В исторических папках могут остаться старые JSON/HTML/маркеры. Не удаляй и не мигрируй их автоматически. Для продолжения прочитай только нужные содержательные Markdown-файлы выбранного прогона, объясни фактическое состояние и согласуй перезапись, если она нужна.
