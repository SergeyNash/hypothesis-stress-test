# Hypothesis Stress Test

**Framework version:** 2.18.0

HST — набор инструкций, ролей и Markdown-шаблонов для исследования гипотезы языковой моделью. Модель ведёт процесс в чате Cline; Python не выбирает этапы, не проверяет выводы и не собирает evidence registry.

Новая гипотеза: hst-start. Явное продолжение RUN_DIR: hst-run только для указанной папки. Источники, глубину обработки, изменение гипотезы и реальные развилки согласовывай через диалог: что известно, варианты, рекомендация и причина. Полный прогон разрешает обычную работу без повторных подтверждений каждого этапа. Прямое разрешение пользователя имеет приоритет; не требуй специальных фраз.

Новый прогон изолирован: нельзя читать соседние runs, их входы, outputs или истории как образцы. Для свободного ID достаточно имён непосредственных папок. Читай инструкции текущего этапа по мере надобности, не весь фреймворк заранее.

Пиши содержательные результаты этапов в Markdown. Финальный этап обязательно создаёт оба файла: human_report.md и человекочитаемый human_report.html; отдельное разрешение на HTML не требуется. Удалён HTML-прогресс, не итоговый HTML-отчёт. Нет обязательных JSON, JSONL, маркеров, валидаторов, CLI-переходов и технического RUN PASS. Качество оценивает модель по смыслу: источники, точные ссылки/цитаты, допущения, независимость, ограничения и противоречия. Сообщай, если ошибку нельзя исправить в согласованных границах. Не выдумывай факты ради заполнения шаблона.

Документы читай доступными клиенту средствами. Не запускай поиск/ранжирование/извлечение скриптами HST. Не заменяй их самодельными PowerShell/Python/shell-командами, regex-проверками текста, временными TXT-выгрузками и установкой парсеров. Чтение, поиск и правки выполняй штатными инструментами клиента. Это правило относится к аналитическому прогону; явная задача установки, обновления или разработки фреймворка имеет отдельный объём. Не сканируй всю БЗ ради маленькой гипотезы. Если формат недоступен — сообщи и предложи текстовый экспорт, другой доступный инструмент или продолжение с пробелом; не устанавливай окружение самостоятельно. Для тяжёлой обработки предложи быстро/подробно/пропустить и дождись выбора.

Единственный монитор хода — установленная задача HST · Прогресс. Итоговый human_report.html — отдельный статический отчёт для чтения в браузере напрямую с диска. Модель обновляет обычный progress.md файловым инструментом. Просмотр пассивный, отсутствие/ошибка отображения не блокирует исследование и не запускает его отладку. Нет TUI, VS Code bridge, HTML-прогресса или обязательного HTTP-сервера.

Модель и настройки, если сообщены, сохраняй в run.md дословно. Иначе «не указана». Не угадывай модель по названию Cline. Не меняй исходную гипотезу без согласования.

## Соразмерность работы

Каждый этап добавляет свой вывод, а не копию предыдущих документов. Исследование заканчивается, когда вопросы этапа получили ответ либо явно описан пробел и его влияние на решение. Полный прогон означает прохождение этапов в согласованной глубине, а не исчерпание всех источников. Применяй .clinerules/40-run-quality.md; нерелевантные разделы шаблонов сокращай с коротким объяснением.

Сохраняй основания один раз с точной цитатой, местом и ограничением. Следующие этапы используют эти записи; возврат к оригиналу нужен при конкретном сомнении, противоречии или недостающем контексте. Новая тема/соседняя гипотеза не становится обязательным исследованием из-за наличия файла в БЗ.
