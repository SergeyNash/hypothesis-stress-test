# Контроль самого Python-контроллера: 2.7 → 2.8

Проверка проведена 14 ноября 2026 года на одной Linux-среде, Python 3.12. Использован один и тот же синтетический интеграционный тест полного жизненного цикла с реальным loopback viewer и привязанными исходными фрагментами. LLM не вызывалась. Старый код — состояние 2.7 до этого пакета; новый — 2.8.

| Показатель | 2.7.0 | 2.8.0 |
|---|---:|---:|
| Вызовы семантической проверки этапов | 127 | 56 |
| Полные аудиты внутри контроллера | 3 | 1 |
| Время участка теста, 3 повтора, с | 0.595, 0.56, 0.597 | 0.362, 0.395, 0.351 |

Участок начинается после первоначального setUp тестовых данных и включает запуск HTTP viewer, переходы и проверки; не включает импорты/подготовку fixture, LLM и разрешения инструментов. Независимая финальная проверка самого теста исключена из столбца полных аудитов. Тест сохраняет вызовы start для проверки совместимости; новый штатный путь с next_prepared позволяет не делать повторный start.

Это подтверждение удаления дублирующихся проверок. Это **не** процент ускорения живого Cline и не доказательство, что Python занимал основную часть 53-минутного прогона. Здесь весь участок занимает менее секунды; задержки между командами модели и реальные ожидания нужно измерять отдельно. Малые времена на общей среде не являются аппаратным бенчмарком.

Регрессионные проверки подтверждают: испорченный артефакт обнаруживается следующей командой, повреждённый отчёт не проходит finish, контрольный ввод/каналы не меняются незаметно, пакет с невалидным утверждением не записывается частично.
