# Контрольный запуск pipeline-001

Перед отправкой замените MODEL_LABEL фактическим названием модели и настройками (провайдер, reasoning, режим Cline). Для сравнения версий HST модель и настройки сохраняются одинаковыми. Для сравнения моделей версия HST должна быть одинаковой.

```text
Выполни полный технический контрольный прогон HST pipeline-001.
MODEL_LABEL: <фактическая модель и настройки>

Создай новую изолированную папку runs/HYP-YYYY-MM-DD-NNN с очередным свободным ID. Существующие прогоны не продолжай и их результаты не читай. Это явное разрешение создать новую папку и выполнить весь прогон.

Возьми FRAMEWORK_DIR/benchmarks/pipeline-001/hypothesis.md. Скопируй в RUN_DIR/input/hypothesis.md дословно: замени только {{HYPOTHESIS_ID}}, {{DATE}} и {{RUN_ID}}. Не переформулируй гипотезу, контекст или роли. Статус при старте draft.

Подготовь прогон одной штатной командой:
python <FRAMEWORK_DIR>/scripts/run_control.py prepare --run-dir <RUN_DIR> --mode full --benchmark-case pipeline-001 --model-label "<MODEL_LABEL>"

Все три источника я явно отключаю для этого запуска: локальная БЗ, Confluence и интернет. Примени это через sources-set --local no --confluence no --internet no с основанием «Явный выбор пользователя в контрольном сценарии pipeline-001». Не спрашивай этот выбор повторно. Инструкции/шаблоны/ролевые материалы самого фреймворка можно читать: они не являются эмпирическими данными заказчика.

Проверку полноты найденных материалов явно пропускаю: зафиксируй retrieval review как waived с этим основанием. Другие проверки качества и финальный аудит сохраняются. Синтетические ролевые ответы не считать доказательствами.

Продолжи hst-run для этого RUN_DIR до human_report.html и finish. Для каждого готового этапа вызывай один complete, без предварительного check-phase; для human_report один finish. check-phase нужен только для отдельной диагностики, не как обычный шаг. Утверждения одного этапа регистрируй через audit_records.py batch-claims. Сроки и объём артефактов пока не сокращай произвольно: это проверка оптимизации контроллера.

В финале сообщи результат проверки, ограничения и путь к outputs/performance_summary.json. Не выдавай незарегистрированное время за время размышления модели. Не обещай подтверждение спроса: это технический тест без эмпирики.
```
