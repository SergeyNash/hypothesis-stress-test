# Оптимизация pipeline: план и состояние

Цель — сократить повторную работу и переходы между моделью и инструментами с сохранением рисков, источников, критического разбора и финального аудита.

## Пакет 1 — 2.8.0

- [x] Фиксированный pipeline-001 с контролем исходной карточки и каналов, ручной меткой модели и версией фреймворка.
- [x] Пассивные замеры существующих CLI: wall/CPU, число команд, реальные вызовы проверок и FAIL/ERROR. Никаких дополнительных команд для модели ради секундомера.
- [x] Отдельные зарегистрированные ожидания и неразмеченное время; пересечения не складываются. Пропуски журнала не выдаются за thinking time.
- [x] Один семантический gate внутри complete, один полный аудит внутри finish; повторный вызов после изменения файлов проверяет их заново.
- [x] next_phase/next_prepared убирает повторный start в штатном full-run, check-phase оставлен для диагностики.
- [x] Пакетная регистрация утверждений с проверкой всех записей перед одной записью ledger.
- [x] Регрессии повреждённых файлов/отчёта, отклонения контрольного ввода и источников, атомарности валидации batch, read-only старых архивов и standalone validate_runs.
- [x] Контрольный тест самого контроллера до/после: [результаты](../benchmarks/pipeline-001/controller-results.md).
- [ ] Пользовательские контрольные прогоны одной LLM до/после, с учётом ожиданий. Ускорение живого Cline до этого не заявляется.

Сценарий: [pipeline-001](../benchmarks/pipeline-001/README.md), готовое сообщение: [prompt.md](../benchmarks/pipeline-001/prompt.md).
