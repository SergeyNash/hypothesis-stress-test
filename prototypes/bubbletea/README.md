# HST · Bubble Tea — первый прототип

Небольшой отдельный интерфейс для тестирования терминальной навигации. Основной HST и его терминал Rich продолжают работать как раньше.

## Windows — без установки Go

Готовые сборки: [GitHub Actions → Bubble Tea prototype](https://github.com/SergeyNash/hypothesis-stress-test/actions/workflows/bubbletea-prototype.yml) → успешный запуск нужного коммита/ветки → **Artifacts → hst-bubbletea-windows**. Для Linux — `hst-bubbletea-linux`. Для скачивания может понадобиться вход в GitHub.

Распакуйте ZIP полностью. В терминале VS Code, открытом в распакованной папке:

```powershell
.\hst-tui.exe --demo
```

Можно также дважды щёлкнуть `start-demo.cmd`. В демонстрации нет обращений к модели, интернету или базе. События и результаты синтетические, настройки реальных прогонов не меняются.

1. Стрелками выберите демонстрационный прогон, Enter.
2. В «Источниках» переключайте пункты Space или 1/2/3; Enter открывает журнал.
3. Первый демопрогон движется сам. Когда появится выбор глубины анализа, ответьте 1/2/3.
4. В журнале ↑/↓ и PgUp/PgDn прокручивают события, Home возвращает свежие. P ставит только демонстрацию на паузу.
5. O открывает демонстрационный HTML в браузере, Q закрывает приложение.

Tab/Shift+Tab переключают экраны; R сбрасывает выбранную демонстрацию.

## Посмотреть настоящий прогон

```powershell
.\hst-tui.exe --workspace "C:\Users\SSiniakov\Documents\DataB"
```

Список HYP-папок и журнал обновляются каждую секунду. С версии HST 2.7.0 новая строка подготовки показывает состояние hst-start ещё до создания HYP-папки: действие, ожидание ответа или ошибку. Она видна на всех экранах, даже при выбранном прошлом прогоне. Это отдельная сессия подготовки, а не вымышленный прогон; после bootstrap она исчезает, новая папка появляется в списке. Функция требует обновлённых правил и новой сборки EXE; начальное внутреннее рассуждение модели до первого инструмента не измеряется. Здесь приложение только читает файлы. Оно не запускает Cline, не меняет активный RUN_DIR, не меняет настройки источников и не управляет паузой реального пайплайна. Экран источников показывает сохранённый выбор (включён / отключён / нет данных) отдельно от событий чтения, использования и последнего обращения. Переключатели доступны только в демонстрации. Отсутствие событий означает, что обращения не записаны; включение источника само по себе не подтверждает чтение. O открывает существующий Human Report выбранного прогона.

Проверяем удобство выбора прогонов, переключателей, прокрутки и читаемость в Windows Terminal/VS Code. Управление исполнителем и сохранение настроек требуют отдельного подтверждаемого канала команд — это следующий этап.

## Сборка разработчиком

Bubble Tea v2.0.0 закреплён в go.mod. Нужен Go >=1.24.2; CI использует Go 1.26.

```sh
go mod tidy
go test ./...
go build -o hst-tui .
```

Отдельный CI запускается на push и pull request, затрагивающие `prototypes/bubbletea/**` или `.github/workflows/bubbletea-prototype.yml`. Он выполняет проверки и сборку Windows/Linux, затем сохраняет готовые файлы как артефакты запуска. Сборка происходит на GitHub до скачивания пользователем.

## Обновление и выход

Общий `.hst/update.py` обновляет фреймворк и установленный Python-просмотр **HST · Прогресс**, но пока не скачивает и не заменяет `hst-tui.exe`. Исходники прототипа входят в репозиторий; готовая сборка доставляется отдельно через артефакты Actions.

Перед заменой EXE выйдите из приложения через **Q**. Если Windows продолжает сообщать, что файл занят, найдите фактический процесс через «Монитор ресурсов → ЦП → Связанные дескрипторы». Диагностика блокировок описана в [основном README](../../README.md#если-windows-блокирует-обновление-или-exe).
