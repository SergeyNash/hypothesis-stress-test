# HST · управление через Bubble Tea

Настройка нового прогона, запуск задачи Cline, ответы на вопросы и просмотр журнала в одном терминальном приложении. Исторические прогоны доступны только для чтения. Go на компьютере пользователя не нужен.

## Первая установка в DataB

Нужны VS Code, уже настроенный Cline и Python 3.10+. Откройте **одну** папку DataB в VS Code. Примените актуальные правила фреймворка обычным обновлением. Скачайте готовую сборку из [Actions → Bubble Tea prototype](https://github.com/SergeyNash/hypothesis-stress-test/actions/workflows/bubbletea-prototype.yml): успешный запуск нужного коммита → **Artifacts → hst-bubbletea-windows** (Linux: hst-bubbletea-linux). В архиве есть EXE и VSIX модуля связи.

Распакуйте архив в отдельную папку. Из её терминала выполните один раз:

```powershell
.\hst-tui.exe --workspace "C:\Users\SSiniakov\Documents\DataB" --install
```

Команда находит фреймворк через `.hst/workspace.json`, копирует EXE в `.hst/bin` и устанавливает **HST Pipeline Bridge** в VS Code. Модуль вызывает публичные методы API установленного Cline: `startNewTask` и `sendMessage`. Модель, ключи, MCP и разрешения остаются в Cline. CLI Cline с отдельной авторизацией не нужен.

После установки **перезагрузите окно VS Code**. Терминал **HST · Управление** откроется автоматически. У старой задачи **HST · Прогресс** отключается автоматический запуск, остальные задачи сохраняются. Вручную открыть управление можно командой палитры **HST: Открыть управление**.

Если `code` не найден, установщик покажет путь VSIX для ручной установки через **Extensions: Install from VSIX…**. Если Cline не установлен/его API недоступен или окно не доверенное, запуск не будет выдан за успешный. Модуль работает с одной папкой рабочего пространства; неоднозначный multi-root запуск отключён.

## Новый прогон

1. Нажмите **N**. Откроется форма до создания папки прогона.
2. Введите гипотезу, выберите профиль, заполните домен, аудиторию, сценарий и роли. Роли разделяются `;`; для сервиса укажите стороны customer/provider. Неизвестные сервисные поля сохраняются как неизвестные и уточняются исполнителем.
3. Выберите локальную БЗ, Confluence и интернет. Для локальной БЗ можно указать существующие папки относительно DataB через `;`; пустое поле означает всю базу. Отключённая БЗ не допускает списка папок.
4. Проверьте настройки. **Enter на экране проверки — «Запустить новую задачу Cline»**. До этого Esc отменяет форму без создания папки.
5. После запуска интерфейс различает **«Настройки сохранены» → «Передано Cline» → «Cline принял запрос»**. Последний статус требует реального вызова подтверждения из задачи Cline. Появление папки или успешный вызов API не считаются таким подтверждением.
6. Экран переключается на новый журнал. Источники применены в run_config.json и ограничивают сбор данных до анализа. Прежние прогоны не меняются.

Управление формой: **Tab / ↑ / ↓** — поле, **← / →** — профиль или тип, **Space** — источник, **Alt+Enter** — новая строка в гипотезе/сценарии, **Enter** — далее. Вставка текста поддерживается. После закрытия TUI состояние запроса и текущий вопрос восстанавливаются; повторного запуска задачи не происходит.

На время одного управляемого прогона не переключайте Cline на другую задачу: публичный API отправляет сообщения в текущую задачу, а не в произвольный task ID. Одновременно поддерживается один TUI-запуск на базу. Явный запуск новой задачи Cline может закрыть предыдущую текущую задачу — это указано на экране проверки.

## Вопросы исполнителя

Уточнение гипотезы, полнота материалов и глубина анализа приходят в TUI. Выберите вариант **1–8** либо введите свободный ответ и нажмите **Enter**. Интерфейс различает сохранённый ответ и его получение исполнителем. Ответы привязаны к request ID, question ID и RUN_DIR; устаревшие ответы и повторная отправка отклоняются. После ответа применяются обычные проверки: выбор глубины анализа сам по себе не разрешает отключённые источники или обход валидации.

Нативные разрешения на инструменты и вход в сервисы по-прежнему обрабатываются в Cline. Модуль не нажимает кнопки подтверждения инструментов и не включает auto-approve. Если связь прервана или Cline не выполняет handshake, виден фактический статус; автоматического повторного запуска задачи нет.

## Просмотр и демонстрация

```powershell
.\hst-tui.exe --workspace "C:\Users\SSiniakov\Documents\DataB"
.\hst-tui.exe --workspace "C:\Users\SSiniakov\Documents\DataB" --new
.\hst-tui.exe --demo
.\hst-tui.exe --version
```

В старых прогонах источники недоступны для переключения; выбранный канал и фактические обращения показаны отдельно. **Tab** меняет экран; **↑/↓**, **PgUp/PgDn**, **Home** прокручивают журнал; **O** открывает отчёт; **Q** выходит из просмотра, **Ctrl+C** — из любого экрана. Закрытие приложения не останавливает Cline.

Демо синтетическое и не пишет реальные прогоны: переключатели, пауза P и ответы 1/2/3 работают без модели. Демо не подтверждает работоспособность связки с установленным Cline. Работу в пользовательском VS Code нужно проверить после установки модуля.

## Обновление

Общий `.hst/update.py` обновляет фреймворк и Python-просмотр. Готовый EXE пока доставляется через Actions. Для замены TUI закройте старый через Q, скачайте новую сборку и повторите `--install`; версия EXE отображается через `--version`. Перезагрузите VS Code для обновления модуля связи. Исходники находятся в этом репозитории, отдельный CLI/провайдер LLM не устанавливается.

## Разработка и проверки

Bubble Tea v2 закреплён в go.mod. Go >=1.24.2; CI использует 1.26. Из этой папки:

```sh
go test ./...
go vet ./...
go build -trimpath -o hst-tui .
```

CI собирает Windows/Linux с версией из VERSION, пакует VSIX, проверяет новый/исторический режимы и поведение клавиш. Python/Node тесты выполняют круг «запрос → создание RUN_DIR → применение источников → подтверждение Cline → вопрос → ответ → подтверждение получения». В тестах заменяется только публичный API Cline; хранилище, Python-контроллер, проверки источников и ID реальные. Эти тесты не заменяют проверку с настоящим расширением пользователя.
