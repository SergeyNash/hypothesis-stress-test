# Лёгкий диалоговый прогон

Модель принимает гипотезу, согласует источники и глубину, создаёт отдельную папку и выполняет содержательные этапы. В точках реального выбора показывает варианты, рекомендацию и причину, получает ответ в чате и сохраняет его в run.md. Обычная разрешённая работа не требует нового подтверждения после каждого шага.

Структура — .clinerules/10-artifact-contracts.md, прогресс — .clinerules/30-run-observability.md. Карточка input/hypothesis.md; результаты этапов outputs/*.md и финальный outputs/human_report.html; текущая заметка progress.md; указатель .hst/active-run.md. Никаких Python-команд, технического аудита, payload и машиночитаемых реестров для начала, перехода и завершения.

Документы читает модель доступными инструментами клиента. Не все локальные модели/клиенты умеют читать PDF/Word/Excel: ограничение объясняется и обсуждается, а не скрывается за генерацией якобы извлечённых фактов. Для большой обработки нужен согласованный объём. В простом прогоне не создаётся собственный код извлечения.

Новая гипотеза не читает прежние runs как шаблоны. Исторические результаты остаются на месте. Для продолжения пользователь выбирает папку, модель восстанавливает состояние по её Markdown и согласует перезапись, если требуется. Старые технические файлы не являются prerequisite для нового результата.

## Работа в согласованной глубине

Сбор оснований сохраняет точные короткие цитаты и контекст один раз. Бизнес-контекст объясняет механизм ценности; рынок отвечает на остаточные внешние вопросы; синтез сопоставляет; план выбирает ближайшие решающие проверки; review проверяет ключевые выводы/ссылки/критерии; отчёт даёт решение и условия. Новые источники нужны для названного вопроса, меняющего решение, а не для заполнения шаблона.

Для внутреннего изменения не требуется полное описание нового продаваемого сервиса. Неприменимое объяснить, неизвестное не скрывать. Вопросы получили ответ либо явно указан пробел — этап закончен. При недоступном чтении ограничить вывод после одной альтернативной штатной попытки; не писать проверочные команды и не отлаживать окружение в прогоне.

## Контрольное повторение

Зафиксировать ту же исходную гипотезу, точное название модели от пользователя, клиент, источники и глубину. Новая изолированная папка, без чтения прежних runs. До начала и после завершения записать доступное фактическое время с часовым поясом; при отсутствии часов — неизвестно, без восстановления по ZIP-времени или монитору. Пользователь может отдельно засечь общий интервал.

Сравнивать общее время и качество решающих выводов. Повторные чтения и технические команды считать только по реально доступной истории клиента; Markdown-сводки не доказывают полную историю вызовов. Фазовые интервалы сравнивать лишь при наличии фактических обеих границ. Не добавлять телеметрию, runtime-журналы или скриптовый бенчмарк; ускорение заявлять только после сопоставимого повторения.
