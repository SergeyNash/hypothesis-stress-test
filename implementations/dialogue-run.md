## Сбой просмотра не меняет ход анализа

Если монитор не читает событие, один раз сообщи, что отображение неполно, и продолжи согласованную содержательную работу. Не изучай terminal_progress.py/run_progress.py, не запускай диагностику визуализации и не переписывай историю ради зелёных этапов. Нельзя дописывать intake/validation completed только из-за того, что они не показаны. Записывай фактическое завершение после реальной работы; неизвестная история остаётся неизвестной. Проверка результата может отдельно сообщить реальную ошибку аудита — её разбираем по существу. Диагностика монитора выполняется отдельной задачей по явному запросу, не внутри контрольного прогона.

# Диалоговый запуск HST (2.9)

Новый прогон ведёт Cline через чат или TUI. Пользователь выбирает источники, глубину, изменения гипотезы и дальнейшие действия; Cline объясняет варианты и рекомендует следующий шаг. Согласованный полный прогон продолжается без повторных вопросов на каждом этапе. Python извлекает данные, считает и проверяет готовые результаты. Он не выбирает следующий этап и не принимает бизнес-решений.

Этот контракт имеет приоритет над старыми командами prepare/start/complete в playbook и phase skills **только для новых execution_driver=dialogue**. Существующие lifecycle_version=1 прогоны продолжаются по прежним правилам. Автоматического понижения audit_version, миграции или очистки истории нет.

## Минимальный старт из чата — без Python

До работы прочитайте только сообщение пользователя, `.hst/workspace.json` при наличии и необходимые части схемы/профиля. Нельзя заранее читать валидаторы, аудиторы и все будущие инструкции. Для свободного ID перечислите только имена непосредственных папок runs, без чтения их содержимого. Запрещены обход старых прогонов, подсчёт строк, поиск успешного образца и копирование старых ledger/review. Для явного продолжения разрешён только указанный RUN_DIR; сравнение архивов — отдельная явно запрошенная задача.

После ясного разрешения на запуск и сохранение карточки используйте обычные инструменты записи файлов. Не запускайте shell/Python ради bootstrap. Повторно проверьте, что новая папка свободна. Не перезаписывайте существующую. Создайте:

- `RUN_DIR/input/hypothesis.md` — согласованная карточка, исходная формулировка дословно;
- `RUN_DIR/run.md` — исходный запрос/согласованный объём и дальнейшие решения;
- `RUN_DIR/run_config.json` — минимальная конфигурация ниже;
- `RUN_DIR/outputs/pipeline_events.jsonl` — первое реальное событие intake/running;
- `KB_ROOT/.hst/active-run.json` — явный указатель для уже установленного просмотра.

Если осталась незавершённая `.hst/startup.json` от старого способа запуска, при явном выборе нового прогона native-записью смените её state на cancelled, сохранив остальные поля и историю; не запускайте старый startup helper. Нельзя выдавать намерение за исполнение. started_at — фактически доступное время регистрации запуска в ISO 8601 с часовым поясом. Не выдумывайте время получения сообщения: если его нет, таймер начинается с регистрации; задержка до неё измеряется по истории клиента отдельно. Не запускайте сервер ради получения URL. Отсутствие просмотра не блокирует анализ.

```json
{
  "protocol_version": 2,
  "audit_version": 2,
  "execution_driver": "dialogue",
  "execution_mode": "full",
  "source_selection_version": 1,
  "timing_version": 1,
  "framework_version": "<значение VERSION установленного фреймворка>",
  "model_label": null,
  "started_at": "<фактическое ISO-время с timezone>",
  "heavy_analysis": "ask",
  "analysis_choices": []
}
```

model_label сохраняется дословно из сообщения пользователя, включая указанные настройки. Если пользователь их не сообщил — null, а в человекочитаемом отчёте «не указана». Не подставлять Claude, OpenAI или другие названия по Cline, интерфейсу, стилю ответа или прошлому прогону. При отсутствии точной модели можно работать, но сравнение моделей будет ограничено.

Указатель — только выбор просмотра, не разрешение на источники и не команда оркестратора:

```json
{"schema_version":1,"run_dir":"runs/HYP-YYYY-MM-DD-NNN","run_id":"HYP-YYYY-MM-DD-NNN","activation_id":"<уникальная метка текущего выбора>","activated_at":"<ISO-время>"}
```

Журнал — JSONL, один объект на строке, возрастающие уникальные id. Используйте реальные события с полями id, at, kind, phase, state, message; для источников добавьте channel, query, urls. Фазы и статусы перечислены в 30-run-observability.

Форма source-события (подставлять только реальные ID, время, текущий этап и фактическую операцию):

```json
{"id":5,"at":"<реальное ISO-время>","kind":"source","phase":"business_context","channel":"internet","state":"declined","message":"Интернет отключён пользователем","query":"","urls":[]}
```

Этот образец не является готовым событием: declined допустим только после реального отказа пользователя. phase — текущий аналитический этап, а не название канала. Если в старой записи этап неизвестен, не выдумывайте его для восстановления истории. Неполный просмотр не является причиной перечитывать весь исходный код монитора.

 Можно обновить файл через native file tool с сохранением всех прежних строк. Не переписывайте существующую историю. Не нужны отдельные shell-вызовы для событий. При сбое записи сообщите, что мониторинг устарел; продолжение не означает, что журнал полон.

Сначала проверьте смысл и полноту карточки по schema/skill, затем начинайте содержательный этап. Записывайте running до его работы, completed только после проверки его готовых артефактов. Не ставьте будущие этапы running автоматически.

## Выбор источников и решения

До обращения к каналу сохраните явный ответ пользователя в source_selection внутри run_config. Неуказанный канал требует уточнения, а не автоматически yes/no. Предпочтение из прошлого запуска не является согласием. Оригинальная карточка и инструкции доступны независимо от локальной БЗ. Широкие поиски по KB должны исключать runs, .hst, копии фреймворка и среды. Даже при local=true чужие результаты не являются источниками нового прогона.

source_selection содержит confirmed=true, channels с тремя bool local/confluence/internet, local_paths (относительные разрешённые папки; [] — вся БЗ при local=true), workspace (абсолютный KB_ROOT), at и reason с фактическим выбором. source_selection_history — список этих же объектов с after_event_id, равным последнему id ДО применения выбора. Запишите source_selection.md. Для отключённых каналов добавьте реальные declined-события, чтобы ограничения и ссылки в quality_review были проверяемы. Прямые native/MCP операции подчиняются тому же выбору: отдельная команда require-source перед каждым действием не требуется. Extraction helpers сохраняют внутреннюю проверку разрешений.

Тяжёлая обработка, полнота инвентаризации, исправление гипотезы и изменение области обсуждаются один раз в точке реального выбора. Покажите факты/неизвестное, варианты и рекомендацию с причиной. Сохраните реальный ответ в run.md и его эффект в конфигурации/артефакте. В TUI используйте существующий ask/consume-протокол доставки; это не автоматический выбор этапов. В чате достаточно диалога и native-записи. Не просите одобрять уже разрешённую обычную работу.

При всех отключённых источниках не сканируйте БЗ, не делайте запросов и не имитируйте исследование. Пустые snapshot/ledger создаются native-записью только когда они нужны артефактам: source_snapshot={"schema_version":1,"files":[],"captures":[]}, claim_ledger={"sources":[],"claims":[]}. quality_review берётся из templates/quality_review.json и заполняется по текущему прогону. templates/claim_ledger.json содержит образцы — НЕ копировать их как факты! Внешнее исследование получает declined с реальным event ID и limitation_target; не вызывать нарочно MISSING_SEARCH_TRACK. Сохраняются unknown, пробелы, синтетическая природа ролей и явные ограничения всех каналов в HTML.

## Проверка результата, а не управление процессом

Скрипты допустимы для реального извлечения/расчёта, регистрации цитат/утверждений и проверки существующих файлов. Никакого тестирования валидатора искусственными ошибками в пользовательском прогоне. Читайте код только для конкретной возникшей ошибки; не разбирайте весь checker заранее.

После создания артефактов этапа:

```text
python <FRAMEWORK_DIR>/scripts/validate_runs.py --run-dir <RUN_DIR> --phase <phase> --save-report --json
```

Для business_context с реальным отсутствием контекста: --completion-status skipped_missing_context. Команда только проверяет и сохраняет фактический результат/историю. Она не создаёт маркеры, не запускает viewer, не включает источники и не выбирает следующий этап. После PASS Cline native-записью создаёт канонический маркер из 10-artifact-contracts и completed-событие. На FAIL покажите причину и исправьте её в согласованных границах либо обсудите изменение; до решения не объявляйте этап проверенным. Не подменяйте фактический технический FAIL произвольным PASS.

После готового HTML — одна полная проверка:

```text
python <FRAMEWORK_DIR>/scripts/validate_runs.py --run-dir <RUN_DIR> --pending-report --save-report --json
```

После PASS запишите итоговый marker/event, input status completed, run_state=completed и ended_at. При явной отмене: run_state=cancelled и ended_at; не писать completed-маркеры. Ошибка сама по себе не останавливает общий таймер: исправление тоже занимает время. Чистый read-only запуск без --save-report остаётся неизменяющим архив. Старые startup_events.jsonl теперь являются допустимым служебным артефактом, их не нужно удалять ради PASS.

## Наблюдение и границы

Мониторы читают явный указатель и текущий журнал, не выбирают «последний» архив по времени. Общее время пересчитывается при отрисовке, без записей каждую секунду. Оно начинается с started_at либо с первого доступного события (так и подписывается), фиксируется на завершении/отмене и восстанавливается после перезапуска. Время ожидания входит в общее. Точность не выше исходных timestamps; пропуски не объявляются временем размышления.

TUI может создать те же файлы до передачи в Cline: Python здесь внутренний транспорт интерфейса, а не цепочка команд модели до анализа. Новый bootstrap не вызывает run_control.prepare, не запускает HTTP и не выбирает следующий этап. Acknowledge подтверждает доставку и снимает блокировку источников; смысл карточки проверяется в диалоге. Финальный технический PASS не заменяет решение о гипотезе.
