# HST · Прогресс

Единственный интерфейс просмотра — задача VS Code **HST · Прогресс**. Она запускает один долгоживущий Python/Rich-процесс, читающий только Markdown текущего явно выбранного прогона. Нет HTTP, TUI, модулей связи, фоновых Python status-процессов и автоматических решений.

Подключение из корня DataB:

```powershell
python .\hypothesis-stress-test-main\scripts\setup_workspace.py --workspace . --terminal --apply --replace-framework-files
```

Открыть: Terminal → Run Task → HST · Прогресс. Автоматический запуск при открытии папки зависит от штатного разрешения VS Code на automatic tasks. Скрипт не устанавливает зависимости при открытии окна — только при явной установке --terminal.

Модель записывает .hst/active-run.md и RUN_DIR/progress.md по .clinerules/30-run-observability.md обычными файловыми инструментами. Таймер вычисляется при отображении без записей каждую секунду. Нет времени начала/окончания — показывается это ограничение. Некорректная заметка показывается как текст, не блокирует исследование и не заставляет модель чинить монитор.

Ctrl+C закрывает только просмотр. Для одного снимка:

```powershell
python .\hypothesis-stress-test-main\scripts\terminal_progress.py --workspace . --once
```

Отметка «выполнено» появляется после успешного сохранения результата, не по плану будущих файлов. Начало/окончание фаз и прогона — только фактическое доступное время с часовым поясом; модель не получает его из счётчика монитора или терминальной команды. Если часы недоступны, записать «время не получено» и не заявлять точную длительность.
