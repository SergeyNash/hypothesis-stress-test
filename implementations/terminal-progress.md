# Прогресс в отдельном терминале VS Code

Просмотр Rich/Click читает тот же `outputs/progress.json`, что и HTML. Не запускает исследование, не меняет артефакты, не требует HTTP и не выбирает «самую свежую папку» по времени. После завершения результат остаётся видимым до следующего явно активированного прогона.

## Подключение в DataB

Откройте в VS Code **корень базы DataB**, внутри которой лежит папка фреймворка. В терминале сначала проверьте изменения:

```powershell
python .\hypothesis-stress-test-main\scripts\setup_workspace.py --workspace . --terminal
```

После проверки списка примените обновление:

```powershell
python .\hypothesis-stress-test-main\scripts\setup_workspace.py --workspace . --terminal --apply --replace-framework-files
```

Используйте фактическое имя папки скачанного фреймворка. Если открыт сам фреймворк, путь начинается с `.\scripts\setup_workspace.py`. В macOS/Linux используется `python3` и `/`.

`--terminal --apply` явно подключает дополнительный просмотр: создаёт изолированную `.hst/terminal-venv`, устанавливает optional-зависимости из `requirements-terminal.txt`, добавляет задачу `HST · Прогресс` в `.vscode/tasks.json`. Обычная установка без `--terminal` этого не делает. При недоступном интернете установка зависимостей сообщит об ошибке; повторите ту же команду после устранения причины. Открытие папки само по себе не устанавливает пакеты.

В существующем `tasks.json` сохраняются другие задачи, inputs, комментарии и их форматирование. Обновление изменённой задачи HST требует `--replace-framework-files`. Некорректный JSONC или повторяющиеся HST-метки останавливают установку до записи конфигурации. Настройки автоматического разрешения задач и доверия папке установщик не меняет.

## Первый запуск в уже открытой папке

Выберите **Терминал → Запустить задачу → HST · Прогресс**. Появится отдельный встроенный терминал. В нём можно видеть «Ожидаю запуска гипотезы в Cline» ещё до существования RUN_DIR. Разверните панель терминала для удобного отображения журнала слева и этапов справа; при малом размере есть компактный режим.

Задача настроена на запуск при открытии папки (`runOn: folderOpen`). VS Code может один раз запросить разрешение автоматических задач для этой доверенной рабочей папки. Разрешите его через штатное уведомление либо `Tasks: Manage Automatic Tasks`. Если автозапуск запрещён, задачу всегда можно запустить вручную. Для уже открытого окна автозапуск не срабатывает задним числом: запустите задачу один раз или заново откройте папку.

Терминал закреплён за задачей (`panel: dedicated`), лимит экземпляров — один. Команды Cline и других задач выполняются в других терминалах. Это задача встроенного терминала, а не отдельное окно PowerShell/Windows Terminal. Из обычного Python-процесса мы не обещаем открыть вкладку VS Code: её создаёт штатный механизм Tasks.

## Как подключается новый прогон

1. Пользователь подтверждает вход и папку прогона в Cline.
2. `run_control.py prepare --run-dir <RUN_DIR>` проверяет вход, инициализирует журнал и записывает `.hst/active-run.json` в корне рабочей папки **до** старта HTTP viewer.
3. Терминальный просмотр замечает новую активацию и читает журнал этого прогона с первых этапов.
4. При переключении на новую гипотезу старые данные очищаются сразу, даже если новый progress.json ещё не появился.
5. Во время временной ошибки чтения остаётся последний снимок только того же прогона, с предупреждением. Удалённый/некорректный указатель не заставляет показывать случайный старый прогон.

Для стандартного `KB_ROOT/runs/HYP-...` корень определяется автоматически. Для другого расположения внутри базы передайте `--workspace <KB_ROOT>` в prepare. При явном возобновлении/выборе существующего прогона можно активировать его без повторного анализа:

```powershell
python .\hypothesis-stress-test-main\scripts\run_control.py activate --run-dir ".\runs\HYP-2026-11-11-002"
```

Само создание новой папки или файл с более свежим временем не переключает экран. При нескольких параллельных прогонах отображается последний **явно активированный**; продолжение другого этапа само по себе не меняет выбор. Для переключения используйте activate. Никакая история событий при переключении не переносится между гипотезами.

## Восстановление просмотра

После Ctrl+C либо закрытия терминала запустите задачу `HST · Прогресс` снова. Cline и прогон продолжают работу независимо. При смене расположения папки фреймворка повторите setup_workspace с `--terminal`, чтобы обновить путь задачи. Среда зависимостей остаётся в базе, а не в заменяемой ZIP-папке фреймворка.

Ручной запуск без VS Code Tasks после установки:

```powershell
.\.hst\terminal-venv\Scripts\python.exe .\hypothesis-stress-test-main\scripts\terminal_progress.py --workspace .
```

Снимок состояния без живого экрана: добавьте `--once`. Проверка демо: вместо `--workspace .` используйте `--demo` или `--demo --scenario waiting|error`. Демо не пишет прогон. При выводе в файл автоматически используется один статический снимок.

## Границы

Полоса показывает долю завершённых этапов, не оценку времени до конца. Статус источника — последнее записанное действие, не сертификат полноты исследования. Если агент не пишет события, просмотр не может восстановить их сам; отображается возраст последнего события. 10/10 не подменяет проверку run_validation.json и решение человека.

Автотесты проверяют конфигурацию Tasks, безопасное объединение JSONC, ожидание/переключение и реальный процесс в Unix PTY. Работу интерфейса VS Code/разрешения автозапуска на Windows необходимо проверить в пользовательском окружении.
