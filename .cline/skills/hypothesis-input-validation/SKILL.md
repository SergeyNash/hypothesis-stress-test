# Проверка входа

Прочитай только карточку текущего прогона и относящуюся к ней схему/профиль. Проверь: что меняем, для кого/в каком контексте, какой наблюдаемый результат ожидаем и что может опровергнуть гипотезу. Формат «если — то» полезен, но не обязателен.

Нужны понятная формулировка, релевантные роли, домен, аудитория и сценарий. Не добавляй все роли автоматически: выбери необходимые перспективы (обычно до пяти), лишние согласуй. ID гипотезы должен соответствовать папке, дата/название нужны для навигации. Пиши замечания обычным языком, без кодов ошибок и объектов validation.

Для service_business используй profiles/service-business.md: тип гипотезы, владелец решения, текущий способ, результат заказчика, обещание и границы, изменение поставщика, стороны ролей. Явное «неизвестно» — исследовательский пробел, а не повод выдумывать факт.

Если существенное неясно — собери связанные вопросы в один короткий диалог, объясни варианты и рекомендацию. При изменении исходной формулировки покажи её и согласуй. Не требуй повторного подтверждения уже ясного ввода. После достаточного прояснения переходи к содержательной работе без скриптов.
