# Рыночный слой

Прочитай вход, решение об источниках в run.md, релевантные основания evidence_inventory.md/external_research.md и вывод бизнес-контекста (либо missing_business_context.md). Для service_business применяй раздел Market [профиля](../../../profiles/service-business.md). Не требуй technical status files.

## Вопросы

Есть ли основания считать проблему реальной, как её решают сейчас, кто/как покупает и что мешает переходу? Для внутреннего улучшения проверяй только связанные с решением внешние допущения; не создавай новый рынок для изменения собственного процесса.

## Работа с основаниями

Сначала используй сохранённые EVID/EXT и их ограничения. Не перечитывай все источники и не повторяй внешний обзор бизнес-контекста. Новый поиск/документ — для конкретного остаточного вопроса, способного изменить решение; только в согласованных каналах и глубине. Существенное расширение согласовать. Соседнее исследование другой услуги не превращать в обязательную часть текущей задачи.

Различай четыре канала: Local KB, Confluence, External, Inferred. Отключённый или недоступный канал — ограничение покрытия, не отсутствие спроса. Локальная копия внешнего отчёта сохраняет происхождение; она не является свежей независимой проверкой. Inferred — интерпретация, не дополнительный источник.

Если необходим внешний поиск, используй external-business-research с остаточным вопросом и уже найденными основаниями. При отказе доступа сообщи фактическое ограничение; после одной ограниченной попытки штатным инструментом зафиксируй пробел, не отлаживай клиент. Не выполнять проверки текста через терминал.

## Результат: outputs/market_analysis.md

- Покрытие четырёх каналов — кратко и фактически.
- Новые для решения рыночные выводы: тезис → EVID/EXT/прямая ссылка → сила и ограничение → влияние на гипотезу. Не копировать всю историю источников.
- Проблема, существующее решение, путь покупки, барьеры — только применимые вопросы; для внутреннего процесса объяснить неприменимость отдельной покупки.
- Опровергающие данные/противоречия и оставшиеся пробелы, которые способны изменить решение.
- Короткий итог для синтеза; степень поддержки относить к конкретному выводу, не ко всей БЗ одним словом strong.

Маркетинговое письмо/наша гипотеза подтверждают предложение, не запрос покупателя и не полученный результат. Сделка подтверждает покупку, не причинный эффект механизма. Не переносить оценки рынка ИИ на весь ИТ-сервис без основания; разные выборки/периоды сами по себе не противоречие.

## Завершение

Вопросы получили ответ либо явный пробел и влияние — поиск закончен. Не добирать источники ради полноты. Проверь ключевые переходы по .clinerules/40-run-quality.md, сохрани результат, отметь завершение в progress.md и перейди к hypothesis-synthesis.
