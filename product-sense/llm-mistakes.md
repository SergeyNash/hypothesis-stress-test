# Типичные ошибки обычного LLM vs агентный конвейер

Материал для слайдов Product Sense. Каждая ошибка — контраст «один чат» vs «стресс-тест».

---

## 1. Принимает логичную формулировку за доказанную

**Обычный LLM:** «Гипотеза выглядит разумной. Рекомендую реализовать.»

**Конвейер:** слои «Роли» + «Рынок» + «Синтез» помечают **внутреннюю иллюзию** — внутренняя логика сильна, внешних доказательств нет.

**Пример:** AppSec — «раньше сканируем → меньше риск в проде» без телеметрии.

---

## 2. Смешивает сигналы в одном ответе

**Обычный LLM:** В одном абзаце: мнение PM, цитата из интервью, «рынок растёт», предположение.

**Конвейер:** слои **независимы** до синтеза. Инвентарь evidence атомарен. Каналы: локальная KB / Confluence / внешние / выведенные.

**Правило:** нет доказательств — нет утверждения.

---

## 3. Сглаживает противоречия

**Обычный LLM:** «Есть некоторые риски, но в целом идея перспективна.»

**Конвейер:** синтез **не ищет консенсус**. Ключевые дивергенции с приоритетом HIGH обязательны.

**Пример:** HR — скорость vs compliance; AppSec — контроль vs governance.

---

## 4. Предлагает «строить» вместо валидации

**Обычный LLM:** Roadmap, user stories, scope MVP.

**Конвейер:** Decision Review → **продолжить с валидацией** + план проверки с минимальными затратами.

**Метрика успеха стресс-теста:** дешёвая проверка до backlog, не объём артефактов.

---

## 5. Путает боль пользователя и ценность для покупателя

**Обычный LLM:** «Пользователи страдают → большой рынок → делайте фичу.»

**Конвейер:** Business Context строит цепочку боль → получатель пользы → поведение → **бизнес-эффект**. Отдельно: кто платит?

**Пример:** боль рекрутера в triage ≠ CHRO покупает «скорость» без audit trail.

---

## 6. Генерирует бесполезные CustDev-вопросы

**Обычный LLM:** «Вы бы пользовались AI-ранжированием?» «Сколько бы заплатили?»

**Конвейер:** `validation_questions.md` — только **поведенческие** вопросы о прошлом опыте.

**Запрещено:** гипотетические «а вы бы…».

---

## 7. Не пересматривает формулировку гипотезы

**Обычный LLM:** Уточняет детали в рамках исходной формулировки.

**Конвейер:** синтез → **влияние на исходную гипотезу** → переформулировка проблемы. В отчёте: «Что изменилось?»

**Пример:** снижение риска → операционная эффективность; auto-rank → governed assist.

---

## Как показать на слайде

| Ошибка | Один промпт | Стресс-тест |
|--------|-------------|-------------|
| Логика = доказательство | ✓ часто | ✗ внутренняя иллюзия |
| Смешение сигналов | ✓ | ✗ независимые слои |
| Сглаживание | ✓ | ✗ сначала противоречия |
| «Строить» по умолчанию | ✓ | ✗ путь валидации |
| Пользователь = покупатель | ✓ | ✗ карта ценности |
| «А вы бы…» | ✓ | ✗ поведенческие вопросы |
| Фиксированный framing | ✓ | ✗ явная переформулировка |
