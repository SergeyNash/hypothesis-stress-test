# Четыре контрольных сценария HST

Синтетические материалы позволяют повторить проверку из чистого рабочего пространства. В каталоге [inputs](inputs/) находятся сообщения и документы для модели. [Критерии приёмки](reviewer/) и [результаты контрольного прогона](reviewer/results.md) читает проверяющий после ответов. В рабочее пространство модели их не копируют.

## Подготовка

Из корня клона этой версии выполните команду и распакуйте архив в **новую пустую папку** вне клона. В ней уже есть правила и навыки Cline, дополнительных инструментов не требуется. Работайте в этой папке. Для независимого варианта распакуйте архив ещё раз и начните отдельный чат.

```sh
git archive --format=zip --output=../hst-acceptance.zip HEAD .cline .clinerules profiles templates implementations layers VERSION
```

Открывайте входные файлы в исходном клоне со стороны проверяющего. В чат по одному шагу передавайте текст сообщения и только перечисленные рядом документы. Либо копируйте их в `incoming/` рабочего пространства непосредственно перед этим шагом. Укажите: «Это отдельный учебный сценарий HST. Используй только предоставленные данные, без внешнего поиска и Confluence». Не открывайте для модели клон с будущими сообщениями. Не используйте один диалог для разных вариантов.

| Тикет | Порядок выдачи из inputs | Что проверять |
| --- | --- | --- |
| HST-01 | [01](inputs/01/). В первом чате claim + interview, strategy, cio. Во втором чистом чате те же входы и committee. | Сопоставить два вывода о бюджете и места в источниках. [Критерии](reviewer/01.md). |
| HST-02 | [02](inputs/02/). В первом чате baseline. После двух сохранённых форматов отчёта — pilot, после обновлённого отчёта — owner. В отдельном чате только commercial. | Проверить ограниченный пилот, рекомендацию внедрить, затем решение владельца в начале обоих отчётов. [Критерии](reviewer/02.md). |
| HST-03 | [03](inputs/03/). Передать rules, дождаться сохранения плана и review. Затем отдельным сообщением передать owner. | Сравнить первоначальный review и обновлённый файл плана по всем пяти строкам. [Критерии](reviewer/03.md). |
| HST-04 | [04](inputs/04/). Передать before. После завершения сохранить исходное рабочее пространство для отдельного варианта. Затем resume с документом journal, далее отдельной репликой owner, после неё повторно resume с тем же journal. В копии исходного пространства, в новом чате — resume и только journal-unattributed. | Проверить оба отчёта и run.md, прежние ожидания, повтор той же партии и случай неизвестной причины. [Критерии](reviewer/04.md). |

Для первых двух коротких разборов применяйте инструкции о доказательствах либо сервисный профиль, review и отчёт. Для третьего выберите этапы планирования и review. Для четвёртого запустите обычный полный прогон и затем продолжайте явно указанную папку. Перед очередной репликой сохраните текущие файлы для сравнения **вне рабочего пространства модели**. Сравнивайте смысл, источники, область действия и сохранённые файлы. Положительный пилот HST-02 и смешанный пилот HST-04 относятся к разным учебным случаям.

Штатные проверки репозитория запускаются из клона. Для `--base` укажите коммит целевой ветки до пакета изменений, например `0b37585` для 2.14.0.

```sh
python -m pip install -r requirements-terminal.txt
python -m unittest discover -s tests -v
python scripts/check_version.py --base 0b37585
```

Эти команды проверяют контракты, обслуживание, просмотр прогресса и политику версий. Семантику ответа проверяют в отдельных диалогах по таблице выше.
