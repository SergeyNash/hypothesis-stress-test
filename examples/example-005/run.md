# Пример 005 — развитие сервиса проактивной поддержки

Профиль: service_business. Версия: 2.5.0. Пример целиком синтетический, создан как эталон артефактов, а не отчёт о реальном клиенте или автономном прогоне Cline. completed означает комплектность примера, не валидацию бизнес-гипотезы. Markers фиксируют подготовленные фазовые артефакты.

## Гипотеза развития
Проверяем переход от реактивной поддержки к проактивному обнаружению и ограниченному восстановлению с ИИ. Исходное обещание: −30% воздействия сбоев, +20% обслуживаемых контуров. Эти эффекты пока не доказаны.

## Как читать
Открыть [human_report.html](outputs/human_report.html), затем [карту](outputs/hypothesis_map.md), [решение](outputs/decision_review.md) и [план проверок](outputs/customer_discovery_plan.md). Сырые учебные вводные лежат в kb-samples; каждый EVID сохраняет synthetic provenance.

## Воспроизведение структуры
```bash
python scripts/extract_evidence.py --root examples/example-005/kb-samples
python scripts/validate_runs.py
python -m unittest discover -s tests -v
```

Для собственного прогона создать новый RUN_DIR с собственными ID и входом, а не продолжать этот completed-пример. Выбрать до пяти ролей. Приоритеты, цены и пороги из примера нельзя переносить в реальный бизнес без проверки.

## Полученное направление
Ограниченный пилот: два класса событий, read-only обнаружение и диагностика, затем только отдельно согласуемые действия. Один клиент, проверяемый клиентский эффект, полный учёт труда и критерии остановки. Ни массовые продажи, ни исходное обещание автономности не обоснованы.
