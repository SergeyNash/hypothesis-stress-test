## Карта заинтересованных сторон

| Роль | Связь |
|------|-------|
| Разработчик / аналитик | Испытывает боль, ежедневный пользователь |
| Руководитель команды | Заинтересован в меньших отвлечениях, рискует репутацией при ошибках |
| Технический писатель | Владелец качества контента, получает обратную связь |
| Владелец базы знаний / руководитель IT | Экономический покупатель, контур управления |
| ИБ / DPO | Барьер согласования при доступе к документам |

## Поток создания ценности

```text
Сложный поиск в Wiki (проблема)
  ↓ ИИ-поиск-помощник со ссылками (изменение поведения)
  ↓ Быстрее ответ со ссылкой на страницу (результат для пользователя)
  ↓ Меньше вопросов коллегам и быстрее задачи (заявленный эффект — не доказан)
  ↓ ??? → Покупатель финансирует контур управления и актуальность базы (другой механизм)
```

## Тип бизнес-эффекта

- **Операционный** — сильный для ежедневного поиска (EVID-001, роли)
- **Внедренческий** — средний при росте доверия к Wiki
- **Выручка** — средний через модуль ИИ-поиска **только если** compliance и актуальность устраивают покупателя (EVID-003, EVID-005)
- **Конкурентный** — сильное соответствие стратегии vs встроенный поиск Confluence/Yandex Wiki на цитируемости

Первичный: **операционный** для пользователей; **выручка** для бизнеса — через позиционирование с контуром управления.

## Связь со стратегией

**Низкая** для гипотезы как заявлено («ИИ-поиск → меньше вопросов коллегам → быстрее задачи»).

**Высокая** для переформулировки **поиска-помощника с источниками, сигналом устаревания и петлёй для техписателей** — приоритеты #1, #2 и OKR H1.

Источники: `product-strategy-2026.md`, EVID-005.

## Ключевые риски

- Маркетинг «умного поиска» без программы актуальности документов
- Разрыв между болью пользователя и мотивом покупателя
- Уверенные устаревшие ответы ИИ (повтор провала пилота, EVID-003)
- Доступ к чувствительным документам без согласования с ИБ (152‑ФЗ)

## Ключевые возможности

- Переформулировка: поиск со ссылками + обратная связь техписателям → модуль ИИ
- Метрика «время до проверенного ответа со ссылкой», не «меньше сообщений в чате»
- Снижение дублей через сигналы популярности и владельцев страниц

## Резюме для следующих слоёв

Боль поиска в Wiki подтверждена. Бизнес-кейс для «меньше вопросов коллегам и быстрее все задачи» **не доказан** и **не совпадает с мотивом покупателя**. Strategic fit высокий только после переформулировки. Ожидать внутреннюю иллюзию «проблема только в поиске» и ловушку локальной оптимизации.
