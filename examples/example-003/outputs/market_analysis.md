# Анализ рынка

## Статус MCP

Confluence MCP: не настроен (example run)

## Локальные сигналы

- 3–4 часа в неделю на поиск в Wiki — сильный, EVID-001
- Чат вместо Wiki, дубли страниц — сильный, EVID-002
- Покупатель требует источники, доступы, актуальность — сильный, EVID-003
- Вопросы коллегам не сводятся к поиску факта — средний, EVID-004
- Стратегия платформы знаний: контур управления важнее автономного чата — сильный, EVID-005

## Внешние сигналы (рынок РФ, IT-корпоратив)

- Confluence / Yandex Wiki как стандарт корпоративной документации — сильный, отраслевой паттерн
- Пилоты семантического поиска по внутренним документам с проблемой доверия и доступов — сильный
- Встроенный поиск job-систем улучшается, дифференциация — цитируемость и свежесть — средний
- Доказуемое сокращение вопросов в чате только от ИИ-поиска — слабый

## Сводка сигналов

| Канал | Сила |
|-------|------|
| Локальная база | сильная |
| Внешние (боль поиска) | сильная |
| Внешние (обещание «меньше вопросов коллегам») | слабая |
| Соответствие бизнес-контексту | низкое без переформулировки |
| Окно возможности | СРЕДНЕЕ при переформулировке с контуром управления |

## Валидация проблемы

| Проблема | Статус |
|----------|--------|
| Сложный поиск в корпоративной Wiki | Подтверждена |
| Быстрее находить нужную страницу (со стороны пользователя) | Частично подтверждена |
| Меньше вопросов коллегам | Не подтверждено |
| Быстрее выполнение рабочих задач целиком | Не подтверждено |
| Покупатель финансирует «только умный поиск» | Опровергнуто |
